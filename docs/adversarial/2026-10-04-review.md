## Architecture traced

`main.jsx` enables MSW only with `VITE_MSW=1`, then mounts HashRouter routes.
`api/client.js` attaches identity/admin credentials, reads JSON versus NDJSON,
updates server clock skew and clears identity on 401. `api/hooks.js` polls
public drop/evidence/inventory and private `/me`. `screenFor` derives screens
from server entry state. EntryForm obtains identity, Turnstile and PoW, persists
progress, submits an entry and stores the signed receipt. Results uses a stable
session order ID for redeem/pay; the API owns allocation and inventory.

The display derives venue/drum counts from server data. The judge dashboard
combines live invariants with fetched harness results, falling back to bundled
fixtures. `/verify` currently displays evidence headers; it does not independently
verify bytes, timestamp evidence, ranking or allocation. M2/M3/M4 implementations
are on separate refs and are not part of the current working tree.

The ownership split is sensible, but the claimed proof is circular: local tests
and fixtures agree with one another while disagreeing with producer code.
JSDoc's `keyof ApiPaths | string` does not enforce endpoint compatibility, and
the source OpenAPI YAML is absent locally. A build proves bundling, not contracts.

## Flags, severity, ownership and exit conditions

1. **F01 — High, M1: real invariants crash `/judges`.**
   `JudgeDashboard.jsx:82` dereferences `active_quantity.toLocaleString`, but M3
   returns `active_offer_units`. React rendering reproduces the TypeError.
   Exit: render a real M3 payload successfully and validate its actual fields.
2. **F02 — High, M1: invariant green is not trustworthy.**
   `dashboardData.js:75` defaults missing tiers to an empty loop and only checks
   the old duplicate field. `{entries_with_multiple_offers:0}` reports no failures.
   It also ignores `oversell`, `held_mismatch`, `double_redemption` and negative
   values. Stale data after poll errors can retain the green heading.
   Exit: validate complete finite nonnegative counts and all conservation fields;
   missing, stale or failed evidence must be visibly unavailable or failed.
3. **F03 — High, M1/M4: live harness evidence is replaced by illustrative data.**
   `JudgeDashboard.jsx:18` expects an object with `lottery`; M4 emits an array
   with `lottery_wil`. `profilesOf` reads `tickets`, not `tickets_won`. Absent bot
   metadata is coerced to honest. Exit: accept the real schema, use published
   metrics, preserve unknown classification and explain fallback errors.
4. **F04 — High, M2 integration: PoW is a timer stub.**
   `pow/index.js` ignores challenge, bits and memory; progress is not proof.
   Backend verification rejects a deterministic one-puzzle reproduction.
   Exit: use M2's worker at integration and run its cross-language round trip.
   Do not repair M2-owned files on the M1 branch.
5. **F05 — Critical, M3: database boundary is internally inconsistent.**
   `_Connection.execute` is async; `_one` and `_all` access cursor methods before
   awaiting it, and those cursor methods are also async. Reproduced with the
   actual shipped classes and helpers. `/me`, invariants, draw and the sweeper
   traverse this boundary. Exit: consistent cursor awaiting and Postgres route tests.
6. **F06 — High, M3: FCFS draw policy is not dispatched.**
   `_draw_drop` always calls `lottery_order` and does not select `allocation_mode`.
   A missing rank module additionally falls back to entry-ID sorting. Static
   finding, not a live reproduction. Exit: explicit mode dispatch, no silent
   ranking fallback, tests where FCFS and lottery produce different orders.
7. **F07 — High, M4 integration: “verify” does not yet prove correctness.**
   Current `verify/index.jsx` only displays headers. M4's `artifact` matches
   `application/x-ndjson` with `includes('json')` and parses it as one JSON value;
   expected hash/proof header names differ from M2, and base64 proof needs decoding.
   Exit: genuine canonical bytes and producer headers pass; tampering fails.
8. **F08 — Medium, M1: poll data is not keyed to its resource.**
   `usePoll` retains old data when `load` changes; a drop change can temporarily
   render another drop's `/me` or invariants. Server authorization remains the
   enforcement boundary, but the UI can show the wrong offer. Static finding.
   Exit: resource changes cannot expose prior resource data; test delayed responses.
9. **F09 — Medium, M1: identity and recovery state are split.**
   `EntryForm` captures `signedIn` once while the client clears JWT on 401.
   Storage failures after accepted writes can show an error despite success.
   `payment_pending` with no local order ID has no recovery path beyond another
   device. Exit: expiry permits sign-in again; reconcile successful writes;
   explicitly establish the supported order recovery contract with M3.
10. **F10 — Medium, integration: contract generation is unreproducible locally.**
    `gen:api` references missing `contracts/openapi.yaml`; upstream schemas also
    omit checkout and detailed draw/invariants shapes. Exit: integrate and publish
    complete producer schemas/version before asserting type generation is stable.
